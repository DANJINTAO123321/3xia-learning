## 🏗️ Infrastructure as Code：Terraform vs Pulumi 2026

### 核心区别

| 维度 | Terraform (HCL) | Pulumi (真实编程语言) |
|------|-----------------|---------------------|
| **语言** | HCL 声明式 DSL | TypeScript/Python/Go/Java/C# |
| **逻辑** | 有限，适合简单场景 | 完整语言特性（循环/条件/函数/类） |
| **学习曲线** | 简单，非程序员也能读 | 需要编程语言基础 |
| **状态管理** | 自建 S3+DynamoDB | Pulumi Cloud（开箱即用） |

### Terraform HCL 优势
- **无副作用**：纯声明式，不可能意外调用 API 或打开文件
- **可读性强**：团队成员都能读懂配置
- **一致性**：代码风格统一，新人上手快
- **生态最大**：3,000+ providers（AWS/Azure/GCP/K8s/Cloudflare...）

### Pulumi 优势
- **真实语言能力**：复杂逻辑（如动态资源创建）用 TypeScript/Python 更自然
- **类型安全**：IDE 自动补全，编译时检查错误
- **组件封装**：用 Class 封装基础设施组件（可复用）
- **开箱即用**：Pulumi Cloud 免费版提供状态管理、加密、团队协作

### 状态管理对比

**Terraform**
```hcl
backend "s3" {
  bucket = "my-terraform-state"
  dynamodb_table = "terraform-locks"  # 痛点：需要额外基础设施
}
```

**Pulumi**
```bash
pulumi login  # 直接使用 Pulumi Cloud，免费额度够用
# 或自托管：pulumi login s3://my-bucket
```

### 使用场景建议

**选 Terraform 当：**
- 团队主要是运维/基础设施背景
- 需求相对标准，不需要复杂逻辑
- 已有 Terraform 基础设施和经验

**选 Pulumi 当：**
- 团队有开发背景（熟悉 TypeScript/Python）
- 需要复杂动态逻辑（条件创建、循环、资源嵌套）
- 想把基础设施当代码库来测试和复用

### 对三虾团队的启发

**腾讯云服务器管理**
- Terraform 是更成熟的选择（providers 多）
- 但 Pulumi 的组件化思维值得学习
- 两者都支持腾讯云！
