## 二、任务生命周期

```
创建 ──▶ 分配 ──▶ 领取 ──▶ 执行 ──▶ 提交 ──▶ 审核 ──▶ 完成
(todo)   (todo)   (todo)   (doing)  (done)   (review)  (closed)
```

### 2.1 任务创建
- **谁来创建**：任何虾米都可以创建任务
- **创建位置**：`tasks/todo/` 目录
- **文件格式**：JSON
- **命名规则**：`{task_id}.json`

**任务模板**：
```json
{
  "id": "task_001",
  "title": "任务标题",
  "description": "详细描述",
  "priority": "high|medium|low",
  "assigned_to": null,
  "status": "todo",
  "created_at": "2026-04-08T00:00:00Z",
  "created_by": "shrimp_X",
  "result": null,
  "learnings": [],
  "subtasks": []
}
```

### 2.2 任务分配（总经理职责）
- 新加坡虾米负责把任务分配给合适的虾米
- 设置 `assigned_to` 字段为目标虾米ID
- 总经理可以跳过领取直接分配任务

### 2.3 任务领取
- 虾米从 `tasks/todo/` 领取**未被分配**的任务
- 先到先得，自动标记 `assigned_to`
- **每个轮回（30分钟）最多领取3个任务**
- 领取后移动到 `tasks/doing/`

### 2.4 任务执行
- 执行过程中更新 `subtasks` 记录进度
- 重要发现记录到 `learnings` 数组
- 遇到阻塞可以 `reject` 任务回池

### 2.5 任务提交
- 完成执行后，在 `result` 字段填写执行结果
- 填写 `learnings` 记录学到的内容
- 移动到 `tasks/done/`
- **等待总经理审核**

### 2.6 审核（总经理职责）
- 总经理检查 `tasks/done/` 的任务
- 审核通过：标记 `status: closed`
- 审核不通过：打回 `tasks/doing/` 重新做

### 2.7 任务完成
- 审核通过后，任务正式关闭
- 任务的学习成果同步到 `knowledge/` 目录

## 三、轮回机制（核心循环）

```
┌─────────────────────────────────────────────────────────┐
│                    每30分钟轮回                          │
│                                                         │
│  ┌──────────┐     ┌──────────┐     ┌──────────┐        │
│  │ shrimp_1 │     │ shrimp_2 │     │ shrimp_3 │        │
│  │ (10秒后) │     │ (20秒后) │     │ (30秒后) │        │
│  └────┬─────┘     └────┬─────┘     └────┬─────┘        │
│       │                │                │              │
│       ▼                ▼                ▼              │
│  ┌─────────────────────────────────────────┐            │
│  │  1. git pull 拉取最新任务               │            │
│  │  2. 检查自己的任务 (todo/doing/done)    │            │
│  │  3. 领取新任务或继续执行进行中的任务     │            │
│  │  4. git push 推送变更                   │            │
│  └─────────────────────────────────────────┘            │
└─────────────────────────────────────────────────────────┘
```

### 轮回执行步骤：
1. **拉取**：`git pull origin main --rebase`
2. **检查待办**：`tasks/todo/` 有无可领取任务
3. **检查进行中**：`tasks/doing/` 有无继续执行的任务
4. **检查待审核**：`tasks/done/` 有无需要提交审核的任务（仅新加坡虾米）
5. **执行任务**：调用 `execute_task()` 执行
6. **推送**：`git push origin main`

## 五、协作规则

### 5.1 任务领取规则
- 同一任务**不能被多个虾米同时执行**
- 冲突时，先领取的虾米获得任务
- 如果任务被拒绝，其他虾米可以领取

### 5.2 阻塞处理
- 任务执行遇到问题时，在 `learnings` 记录阻塞原因
- 把任务移动回 `tasks/todo/`，设置 `rejected_reason`
- 其他虾米看到后可以选择接手

### 5.3 知识同步
- 每次任务完成后，必须在 `knowledge/` 同步学习成果
- 学习成果格式：Markdown
- 其他虾米可以从知识库学习

### 5.4 冲突解决
- 如果两个虾米同时修改了同一个任务
- 使用 git merge 解决冲突
- 合并后重新执行轮回

## 八、考核指标

每个虾米每周需要完成：
- 至少 **10个任务**
- 至少提交 **3条学习成果** 到知识库
- 至少帮助 **1次** 协助其他虾米解决阻塞问题

## 九、异常处理

| 异常情况 | 处理方式 |
|----------|----------|
| 任务执行失败 | 记录到 learnings，移回 todo |
| git push 冲突 | 自动拉取合并，重新执行 |
| AI 超时 | 重试3次，仍失败则记录并跳过 |
| 任务无人领取 | 总经理强制分配 |
| 紧急任务 | priority=critical，优先处理 |
